# PRASARA (dulu Kos Hunian) — catatan untuk Claude

PRASARA: platform bisnis multi-usaha, berawal dari SaaS manajemen kos (Next.js App Router + Supabase + Vercel). Pemilik: Dewo, mengerjakan dari HP — semua instruksi ke pengguna harus bisa dilakukan dari HP, dalam Bahasa Indonesia.

## Aturan tetap
- **Setiap perubahan/fitur baru WAJIB ikut memperbarui panduan**, dalam commit yang sama:
  - `app/panduan/page.jsx` (panduan lengkap bergaya buku, langkah bernomor + layar contoh di `components/demo/Screens.jsx`)
  - `lib/guide.js` (isi tombol "? Panduan" per menu; `step` = nomor langkah di /panduan — perbarui bila penomoran bergeser)
  - bila menyangkut paket/harga: `lib/plan.js` (tabel fitur landing & Langganan)
- Perubahan database: tambahkan file baru di `supabase/migrations/` (jangan ubah migrasi lama); Supabase memasang otomatis lewat integrasi GitHub saat push ke `main`.
- Uji migrasi di PostgreSQL lokal sebelum push (pgcrypto ada di skema `extensions` di Supabase — jangan pakai fungsinya tanpa prefiks).
- Push ke `main` = langsung online (Vercel).
- Lokasi stok (migrasi `20261107160000`): `products.stock` = total; `stock_levels` per lokasi diisi trigger `stock_moves_loc` (lokasi dari dokumen ref_id atau `stock_loc(kos)` = lokasi kerja pengguna). Fungsi stok baru cukup insert `stock_moves`; jangan update `stock_levels` langsung. Patch fungsi lama lewat `_prasara_patch` (buat & hapus di migrasi).
- Bisnis ditutup (`kos.closed_at`): trigger `zz_kos_open_guard` menolak tulis dari pengguna di semua tabel ber-`kos_id` (migrasi `20261107170000`). **Tabel baru ber-`kos_id` wajib diberi trigger yang sama**; jadwal harian harus melewati bisnis `closed_at is not null`. Uji isolasi: `supabase/tests/isolasi.sql`.
- Bisnis Jasa & Laundry (migrasi `20261107210000`): tabel `svc_*` (layanan, tahap, pesanan, pembayaran, keluhan, riwayat). Harga dihitung server (`svc_price_lines`); pendapatan diakui saat pesanan `selesai` (diserahkan), pembayaran sebelumnya = uang muka. Peran `operator` (area `ops`) tidak melihat uang. Fitur untuk jenis bisnis lain wajib ikut dicek untuk `jasa` (cari `business_type === 'retail'`).
- Properti lengkap (migrasi `20261107220000`): `deposits` (saldo = terima − kembali − potong; bayar tagihan dari deposit = payment `method='deposit'` yang hanya boleh dibuat `deposit_add`, dijaga trigger `payments_deposit_guard`), `maint_tickets`/`maint_events` (keluhan & perbaikan, portal `portal_report_issue`), `utility_types`/`meter_readings` (meteran → invoice `tambahan`). Laporan kos berbasis kas: deposit masuk/keluar = arus kas, bukan pendapatan.
- Booking kamar (migrasi `20261107230000`): `bookings` mengunci kamar (`start_lease` menolak kamar yang dibooking kecuali lewat `booking_checkin`); DP = akun uang muka sampai check-in (jadi deposit `booking_id`) / refund / hangus (pendapatan lain). Laporan kas: DP masuk saat `dp_date`, deposit dari booking bukan uang masuk baru.
- Business Builder (migrasi `20261107240000`): bisnis `kustom` = `bb_workspace` (draf/aktif) + `bb_objects`/`bb_fields`/`bb_statuses`/`bb_transitions`/`bb_reports`; isi di `bb_records.data` (jsonb) hanya lewat RPC (`bb_clean` memvalidasi tipe, `bb_strip` menyembunyikan field per peran; tabel `bb_records` tanpa policy select). Tanpa SQL/kode bebas. Peran kustom: pengelola, operator.
- Lampiran (migrasi `20261107260000`): tabel `attachments` (tanpa policy select) + Supabase Storage bucket privat `lampiran` (dibuat otomatis oleh `/api/lampiran` dengan kunci server). Izin di DB: `att_target` (entity → area baca/tulis), `att_prepare`/`att_commit`/`att_list`/`att_delete`; file dibuka lewat signed URL 10 menit. Batas paket `lampiran_mb`. Entitas baru yang butuh lampiran: tambah di `att_target`, check `entity`, trigger `att_gone`, dan `ENTITIES` di route. Pembersihan file di cron harian (`att_purge_list`).
- Setup bisnis (migrasi `20261107290000`): pendaftaran `/mulai` multi-kategori → `setup_create` membuat bisnis `kos.setup_status` draf + `setup_items` dari `biz_templates` (kategori/subkategori di `biz_categories`/`biz_subcategories`, diatur Super Admin di /admin/kategori). Status item: draft/needs_information/pending_owner_confirmation/approved/active/rejected/paused; pemilik memutuskan di `/konfirmasi` (`setup_item_save`, `setup_activate` hanya menerapkan yang disetujui lewat `setup_apply`). Bisnis belum aktif: `kos_open_guard` menolak tulis operasional (hanya tabel konfigurasi), halaman publik tersembunyi; fungsi setup memakai flag `prasara.setup_ok`. Jangan isi harga/kapasitas otomatis. Bisnis lama = 'active'. Template baru cukup baris `biz_templates` (spec JSON).
- Laundry lengkap (migrasi `20261107310000`): `svc_zones` (wilayah+biaya), `svc_slots` (jam jemput/antar, kapasitas), kolom `pickup_status`/`delivery_status` di `svc_orders` (trigger default). Pesanan dijemput tidak bisa diproses sebelum `svc_pickup(...'dijemput')`; antar: `svc_delivery` berangkat → terkirim (= `svc_order_move` selesai; operator hanya bila lunas). Modul `j_antar` mengikuti item setup "Antar jemput" (bukan item modul). Dashboard jasa dari `svc_dashboard` (data nyata saja).
- Portal pemesanan (migrasi `20261107320000` & `20261107330000`): permintaan halaman bisnis tanpa pesanan langsung = prospek (`crm_leads`), dicek `lead_check` & dikonfirmasi `lead_confirm` (kos→booking, toko→keranjang Kasir + `lead_mark_sold`). Jasa: pelanggan memilih layanan → `public_order_create` (kunci server) membuat `svc_orders` status `permintaan` (source portal); pemilik `svc_request_confirm`/`svc_request_reject`; pelanggan cek status `public_order_status` (nomor + No. HP) di /b/[slug]/cek. Logo: bucket publik `logo`, path di `kos.profile.logo_path` (`logo_prepare`/`logo_set`, /api/logo).
- Kategori lain (migrasi `20261107340000`): template Builder per kategori dari `biz_templates.spec->'builder_spec'` (`bb_seed_spec`); Kuliner = mesin `jasa` dengan `template_code='kuliner'` (`isKuliner`/`terms()` di `lib/business.js`/`lib/jasa.js` untuk istilah Menu, tanpa jemput), kolom `svc_orders.dine` ('tempat'/'bungkus') + `table_no`, jumlah meja di `kos.profile.tables`, layar `/dapur` (area sell,ops).
- Bagikan & QR (migrasi `20261107350000`): ikon Bagikan di header (`components/Bagikan.jsx`, `share_info` untuk semua anggota — slug hanya bila terbit atau peran settings); QR dibuat sendiri di `lib/qr.js` (tanpa paket npm), poster cetak lewat `body.pq` + `.qrprint`. Ikon tampil di semua bisnis (draf → arahkan ke Pusat Konfirmasi); belum terbit → `public_page_quick_publish` (aktifkan modul `u_halaman` + slug unik dari nama, migrasi `20261107400000`). `Sheet` dirender lewat portal ke `<body>` agar tidak tertutup `.bnav`.
- QR per meja (migrasi `20261107360000`): `/b/[slug]?meja=N` → `public_order_create` dengan `table_no` (dicek 1..`profile.tables`, HP opsional, batas per perangkat 15/jam, harian kuliner 400) → status `permintaan`, dine 'tempat'; jumlah meja diubah lewat `kul_tables_set` (Menu & tahap); kartu cetak di Bagikan (`.qrprint.meja`).
- Meja & reservasi (migrasi `20261107370000`): `kul_reservations` (status permintaan/dipesan/datang/selesai/batal/tidak_datang, `log` jsonb = riwayat, bentrok meja dicek `kul_resv_clash`), RPC `kul_resv_save`/`kul_resv_status`/`public_resv_create` (kunci server); tagihan meja `kul_table_pay` (beberapa `svc_payment_add` dalam 1 transaksi, id = md5(kunci||pesanan) anti dobel) & `kul_table_close`. Halaman `/meja` (area sell).
- Kos ↔ portal (migrasi `20261107380000`): template kos menyarankan modul `p_portal` + item `rekening` (→ `kos.payment_info`) & `peraturan` (→ `kos.house_rules`); `portal_get` ikut mengirim `profile.payment_methods/payment_rules`; `end_lease` menolak tanggal keluar di masa depan (pakai Rencana selesai). Uji alur ujung-ke-ujung kos: `/var/tmp/pgtest/e2e.sql`.
- Pendaftaran penghuni online (migrasi `20261107390000`): `/b/[slug]` kos → `ApplyForm` → `/api/publik/kirim` (apply) → `public_apply` (kunci server) = `crm_leads.apply` + `lead_proofs` (bukti); konfirmasi `lead_confirm`: mode `huni` → `lead_move_in` (occupant + `start_lease` + invoice + payment terverifikasi bila pemilik isi `paid_amount`), `booking` → booking dengan `bookings.applicant` (dipakai `booking_checkin`). `occupants.address` baru; rekening di formulir hanya bila `public_pages.show_payment` (`public_pay_info`).
- Media (migrasi `20261107410000`): foto publik di bucket publik `media` lewat `/api/media` (browser mengirim JPEG full 1600px + thumb 480px; `lib/media.js` crop/putar/posisi); tabel `media` + `media_links` (entity kos_cover/kos_gallery/room/product/service; satu foto banyak pemakaian) + `media_trash`; RPC `media_prepare/commit/link/unlink/main/relink/replace_prepare/replace_commit/delete/caption/list/for`, publik `public_media(slug)`; kuota `lampiran_mb` = lampiran + media (`att_usage`). - Harga V2 (migrasi `20261113100000`): paket `dasar`/`bisnis`/`pro` (+`gratis`; `standar` nonaktif, pelanggan lamanya sudah dipindah ke `bisnis`). `plan_versions.price` = harga yang ditagihkan, `list_price` = harga normal (dicoret); `plan_terms` = paket jangka panjang (Pro 12 bulan = 1.072.800, pembanding 1.788.000 = 12 × 149.000). Harga selalu lewat `plan_eff_price`/`plan_unit_price`/`plan_total` (jangan hitung di frontend selain untuk tampilan). Promosi berakhir otomatis hanya bila `platform_settings.promo_until` diisi. Masa coba: `trial_days` (14) di paket `trial_plan` (dasar), dihitung sejak `setup_activate`; `kos.trial_plan` menjaga masa coba lama (pro). Batas V2 yang SUDAH ditegakkan: karyawan, kamar terisi, ruang lampiran; cabang/produk/pelanggan/ekspor per bulan BELUM.
- Lapisan pembayaran (migrasi `20261113110000`): tagihan `plan_requests` → `pay_transactions` (kode `TRX-…` unik) → aktivasi lewat SATU pintu `plan_activate` (dipanggil `invoice_settle`; `admin_set_plan`/`admin_decide_request`/webhook/rekonsiliasi semuanya lewat sini; riwayat di `plan_activations`). Webhook gateway: adaptor server memverifikasi tanda tangan + menormalkan, lalu `pay_event_ingest` (hanya service_role; idempoten per `provider+event_key`; tidak cocok / tanda tangan tidak sah → `pay_recon`, TIDAK mengaktifkan). `pay_providers.lynk` AKTIF sejak migrasi `20261113150000` (format & tanda tangan terverifikasi dari 2 transaksi nyata; lihat bullet Alamat webhook). Tabel `pay_*`/`plan_activations` sengaja tanpa `zz_kos_open_guard` (catatan penagihan platform, hanya ditulis fungsi). Uji: `supabase/tests/harga_v2_pembayaran.sql`.
- Alamat webhook (Tahap D, migrasi `20261113130000`, mode CATAT SAJA): `POST /api/bayar/<kode>` → `lib/bayarWebhook.js` → `pay_event_catat` (service role) hanya menyimpan notifikasi ke `pay_events` dengan status `diabaikan`, `signature_ok` null, header rahasia tidak disimpan nilainya. Tidak menyentuh tagihan/transaksi/paket. Batas 500/penyedia/hari, isi maks 16 KB. Verifikasi tanda tangan Lynk (dari dokumentasi resmi): `X-Lynk-Signature` = sha256(amount + refId + message_id + merchant_key) hex; kunci dari env server `LYNK_MERCHANT_KEY` (tanpa kunci = hanya dicatat). Tanda tangan cocok → `pay_events.status='diterima'`; tidak cocok → `ditolak` + antrean `pay_recon` (tanda_tangan). Keduanya TIDAK mengaktifkan paket (migrasi `20261113140000`). Sudah TERBUKTI dengan transaksi nyata (13 Nov 2026, Rp 2.000 via QRIS, ref cocok, `signature_ok` true, `cocok_dengan` = kunci_bersih_nominal + kunci_mentah_nominal): nominal di notifikasi = harga produk (2000), BUKAN total yang dibayar pembeli (2014 termasuk biaya layanan Rp 14). Pencocokan paket memakai nominal notifikasi = harga paket; uji metode pembayaran lain dulu sebelum mengandalkannya. Sejak migrasi `20261113150000`: kunci terpasang → `pay_event_ingest` (satu-satunya jalur aktivasi Lynk). Paket aktif HANYA bila tanda tangan sah, sudah dibayar, ref belum pernah dipakai, nominal = harga tagihan, email = pemilik, dan tepat satu tagihan menunggu (`pay_transactions` pending). Selain itu → `pay_recon` untuk admin, paket tidak berubah. Kunci belum terpasang → hanya `pay_event_catat`. Uji: `supabase/tests/webhook_catat.sql`, `supabase/tests/webhook_verifikasi.sql`, `supabase/tests/webhook_aktivasi.sql`.

SET` variabel kustom ditolak di Supabase (bukan superuser).

## Wajib dari blueprint PRASARA (baca sebelum tiap tahap; pemilik tidak mau ada yang terlewat)
- Brand (diperbarui 7 Nov 2026 atas permintaan pemilik, mengikuti contoh desain): charcoal hijau-tua + **emerald** sebagai aksen utama (variabel CSS `--gold` = aksen, sekarang hijau; `--att*` = amber untuk perhatian/peringatan). **Gelap = tampilan bawaan** (app & landing; `data-theme` diset `lib/theme.js`, terang/ikuti HP bisa dipilih); logo P di `components/Logo.jsx`. Minimalis, tanpa gradient mencolok; Plus Jakarta Sans; mobile-first dengan navigasi bawah.
- Tagline: "One Intelligence. Every Business." / "A smarter way to manage life and business."
- Jangan klaim fitur yang belum ada: tandai "Segera hadir"/"Dalam rencana" (WhatsApp otomatis, jenis bisnis lain). Data contoh selalu diberi label DATA CONTOH.
- **Tanpa tampilan/branding AI** (keputusan pemilik 13 Nov 2026, sesuai dokumen harga V2): jangan menambah kartu, menu, bagian landing, atau baris paket tentang AI. (Tab "Tanya asisten" di portal penghuni hanya muncul bila kunci server dipasang — biarkan.)
- Keputusan 13 Nov 2026 (dokumen Project `PRASARA_PAKET_HARGA_MASTER_PROMPT_V2` & master prompt Pendaftaran & Payment): harga V2 = Dasar 49rb (normal 69rb), Bisnis 99rb (139rb), Pro 149rb (199rb), Pro Tahunan 1.072.800 (SUDAH dipasang, lihat Aturan tetap); masa coba 14 hari Paket Dasar; mode Gratis terbatas tetap ada setelah masa coba; pelanggan lama Standar→Bisnis tanpa memotong masa aktif. Pembayaran: Lynk.id lewat 4 link checkout tetap (ada di dokumen V2) + webhook (Merchant Key di env server), pencocokan email+nominal+paket ke invoice `plan_requests`, yang tak cocok → antrean rekonsiliasi admin; QRIS/transfer manual tetap cadangan. Lynk tidak punya API link dinamis/cek status/tagihan berulang yang terverifikasi — jangan diklaim.
- Akun: pendaftaran di `app/masuk/page.jsx` (nama & WhatsApp di `user_metadata`, validasi `lib/akun.js`, verifikasi email + kirim ulang, lupa sandi `?reset=1`); sambutan di `/mulai` (`components/Journey.jsx`).
- Menu menyesuaikan jenis bisnis & peran; jangan tampilkan menu yang tidak relevan.
- Keamanan: otorisasi di server/database, audit trail, tidak menampilkan rahasia, status jujur (Verified/Partial/UI only).
- Sebelum menyatakan selesai: uji (database lokal, esbuild, render statis + screenshot bila UI) dan pikirkan kasus nyata pengguna (mis. barang tanpa barcode, iPhone/Safari).
